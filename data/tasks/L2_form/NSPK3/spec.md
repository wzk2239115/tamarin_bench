## Description of the Protocol: Classic Needham-Schroeder Public Key Protocol (NSPK3)

### Overview
The Needham-Schroeder Public Key Protocol (NSPK3) is a cryptographic protocol designed for secure communication between two parties using public-key cryptography. This version focuses on three messages exchanged between the initiator (I) and the responder (R). The protocol aims to establish a shared secret between the two parties while addressing certain security concerns.

### Participants
- **Initiator (I)**: The party that initiates the communication.
- **Responder (R)**: The party that responds to the initiator's request.

### Goals
The main goals of the NSPK3 protocol are:
1. To securely establish a shared secret between the initiator and the responder.
2. To ensure the authenticity of both parties.
3. To prevent replay attacks through the use of nonces.

### Messages
The protocol consists of three main messages:
1. **Initiator to Responder**: 
   - **Message 1**: The initiator sends a message encrypted with the responder's public key. This message contains:
     - A fixed identifier ('1').
     - A nonce (`ni`) generated by the initiator.
     - The identity of the initiator (`I`).
   
2. **Responder to Initiator**:
   - **Message 2**: The responder replies with a message encrypted with the initiator's public key. This message includes:
     - A fixed identifier ('2').
     - The nonce (`ni`) received from the initiator.
     - A new nonce (`nr`) generated by the responder.
   
3. **Initiator to Responder**:
   - **Message 3**: The initiator sends a final message encrypted with the responder's public key. This message includes:
     - A fixed identifier ('3').
     - The nonce (`nr`) received from the responder.

### Security Assumptions
- A public key infrastructure (PKI) is assumed to be in place, allowing for the secure distribution of public keys and the registration of long-term keys.
- The initiator and responder possess their long-term keys, which are used to encrypt and decrypt messages.
- Nonces are utilized to ensure that each session is unique and to prevent replay attacks.

### Security Properties
The following security properties are verified within the protocol:
1. **Nonce Secrecy**: Ensures that nonces remain confidential from eavesdroppers.
2. **Injective Agreement**: Guarantees that if a party commits to a session, there exists a matching session with the same parameters, preventing impersonation.
3. **Session Key Setup Possible**: Demonstrates that it is possible for honest agents to establish a shared secret without revealing long-term keys.

### Formalization
The formalization of the protocol is constructed in Tamarin using rules that define the actions of the participants, the messages exchanged, and the underlying security claims. The rules account for the generation of nonces, the encryption and decryption of messages, and the handling of session states.

### Conclusion
The NSPK3 protocol serves as a foundational example of public key cryptography in action. While it provides a framework for secure communication, it has notable vulnerabilities that have been addressed in subsequent revisions and protocols.
